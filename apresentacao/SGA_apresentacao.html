Sem listas dentro de um campo.

2FN

Sem dependência parcial

Nada depende de só parte da chave.

  • 8 das 9 tabelas têm chave simples.
  • A única composta (pre_requisito) não tem outras colunas.
  • Em matricula tudo depende do aluno naquela turma.
3FN

Sem dependência transitiva

Cada dado mora em um lugar só.

  • Mensalidade depende do curso, então fica em curso.
  • Nome do professor fica em professor, e a turma só aponta para ele.
  • O faturamento é uma view.
A única redundância, de propósito: media_final e situacao são derivadas das notas, mas os triggers recalculam a cada INSERT e UPDATE, então nunca divergem.

A procedure confere o perfil e faz só UPDATE matricula SET n1, n2, faltas. Não calcula nada.

trg_atualiza_situacao

BEFORE UPDATE (RN01 a RN04). Recalcula media_final e situacao com as mesmas functions, antes de gravar.

O banco confere n1 BETWEEN 0 AND 10 (RN07) e grava a linha já com média e situação certas.

Três armadilhas que o banco escondia

diego
PROBLEMA

O BEFORE UPDATE lê a linha antiga

Chamar fn_situacao(id) no trigger devolvia a situação do lançamento anterior.

Clique para ver a solução
SOLUÇÃO

Regra separada dos dados

A regra foi para uma função que recebe os valores. O trigger passa NEW.* e a fn_situacao(id) só lê a linha e chama a mesma auxiliar.

PROBLEMA

NULL não é diferente de nada

OLD.n1 <> NEW.n1 dá NULL quando a nota era nula, e o primeiro lançamento ficava sem auditoria.

Clique para ver a solução
SOLUÇÃO

O operador <=>

Compara tratando NULL como valor: IF NOT (OLD.n1 <=> NEW.n1). Agora todo lançamento é auditado.

PROBLEMA

6,995 é exame ou aprovado?

A média tem 3 casas, a coluna guarda 2: o boletim mostraria 7,00 com "Em Exame".

Clique para ver a solução
SOLUÇÃO

Arredondar antes de comparar

A situação sempre combina com a média exibida. Na frequência é o contrário: ela é truncada, para 74,996% não virar 75,00%.

Regras de ouro
  • Só CALL e SELECT em view; nenhum INSERT, UPDATE ou DELETE
  • Valores sempre como parâmetros, nunca concatenados
  • Lista de views permitidas

  • Colunas lidas pelo nome, não pela posição
